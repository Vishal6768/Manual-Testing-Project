## 2. Objective

The objective of UI/UX testing is to validate
the visual appearance, usability, accessibility,
responsiveness and overall user experience
of the SauceDemo application.

Testing focuses on identifying interface
inconsistencies, usability issues, layout
problems and navigation difficulties.

## 10. UI/UX Defect Classification

| Defect Category | Description |
|---|---|
| Layout Issue | Incorrect alignment or overlapping content |
| Typography Issue | Font or readability inconsistency |
| Visual Issue | Incorrect or inconsistent visual appearance |
| Design Mismatch | Difference from an approved design |
| Navigation Issue | Incorrect or confusing navigation |
| Usability Issue | Difficulty completing intended actions |
| Responsive Issue | Layout problem at selected viewport |
| Accessibility Issue | Barrier affecting accessible interaction |
| Content Issue | Incorrect or misleading displayed content |
| Functional UI Issue | Interface control fails to perform its action |

## 11. Severity Guidelines

| Severity | Example |
|---|---|
| Critical | UI issue prevents completion of a critical workflow |
| High | Important button or input field is inaccessible |
| Medium | Layout issue affects usability but a workaround exists |
| Low | Minor spacing or cosmetic inconsistency |

Severity will be determined by actual
business and user impact.

## 15. QA Operational Activities

- Review available design requirements.
- Identify UI/UX testing scope.
- Perform screen-level validation.
- Review user journeys.
- Compare approved designs where available.
- Identify design clarification items.
- Track task and defect IDs.
- Perform responsive testing.
- Perform browser compatibility checks.
- Capture visual evidence.
- Classify UI/UX defects.
- Communicate usability risks.
- Retest fixes when available.
- Update QA documentation.

## 16. Exit Criteria

- Applicable UI/UX checks are executed.
- Critical user journeys are validated.
- Selected viewports are tested.
- Selected browsers are tested.
- Identified issues are documented.
- Supporting evidence is maintained.
- Outstanding usability risks are documented.
- Requirement coverage is reviewed.
